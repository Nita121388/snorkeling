Overview · 时间线（甘特）原型

同一份 agent 数据，两种时间口径：G1 会话寿命条（只用现有字段，今天就能做）与 G2 状态分段（需要新增 per-block 状态历史）。切换上方按钮对比；下方写明数据来源与代价。

Agent 会话

G1 会话寿命条 无需埋点

条形 = SessionSummary.createdAt → updatedAt（live 会话延到 now）。

  • 尾巴一段用**当前状态色**（与列头/卡片 chip 同一套 token），历史段中性灰斜纹表示「不知道当时在干什么」。
  • hover 出：provider、项目、消息数、最后活动时间、当前状态词。
  • 无 createdAt 的历史会话 → 从第一天可见的 updatedAt 起算，并在 tooltip 标注 "start unknown"。

G2 状态分段 需要埋点

条形按状态切段（working / blocked / done / idle / stale），每段宽度 = 该状态持续时长。

  • 数据缺口：现在 AgentStatus 只保留「当前态」，没有转移序列，无法回溯着色。
  • 最小实现：agent-status store 里对每个 blockId 留一份环形历史（cap 200 条，localStorage 持久化，约 40 字节/条 → 单块 8KB 上限，全部会话设总预算 1MB + LRU 淘汰）。
  • 写入点只有一处（presented 状态更新时 append），读取走纯函数 buildTimelineSegments(history, window)，可单测。

共同交互与边界

  • 时间窗：2h / 8h / 24h / 7d 四档，默认 8h；窗口外不画条，只在行尾给一个「更早」箭头。
  • 排序：按最后活动时间倒序（最上面 = 刚刚动过的），空会话（updatedAt 超窗）灰显排底。
  • 窄面板：行标签缩到 emoji + 竖排省略，时间轴横向 scroll + snap，不压缩刻度文字。
  • 与看板/列表共用筛选（Agents / Opened Tabs）与「打开会话」点击行为。

建议

先落 G1（零埋点、当天可做、立刻能回答「哪个 agent 起了多久还没结束」）； 真实用一周后如果「期间到底卡在哪」这个问法反复出现，再上 G2 的环形历史 —— 它是一条可独立回滚的小改动，不动时间线的渲染结构（同一份 segments 模型，G1 就是单段带 unknown 尾巴）。

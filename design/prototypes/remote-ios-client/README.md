## 1. 这个原型要解决的问题

手机端第一版是「观察器」：**看 agent 在干什么 + 审批下一步**，不做完整终端。

交互采用微信结构（列表 → 点进对话），目标用户零学习成本；**视觉不照抄微信**，按 app-screen 设计规范重做（见 §0）。

## 0. 视觉系统（v0.2 重做）

| 决策 | 值 | 理由 |
|---|---|---|
| 底色 | `#F5F6F7` 冷灰 + 白卡片 | 安静边框：分离靠 1px 线或色阶，不靠阴影 |
| 动作色 | 深青 `#0C6B63`（发送、同意、当前 Tab） | 一个 accent，只给动作与当前态；约 3-5% 像素占比 |
| 状态色 | 运行 `#1F9D84` / 待审批 `#C9861C` / 离线灰 | 色上数据不上 chrome |
| 头像 | 每个 agent 一个稳定 hue + 淡底色块（Claude 陶土 / Codex 青 / Pi 蓝 / Grok 琥珀） | 身份色，非数据色；同屏相隔 60° 以上 |
| 消息气泡 | 我方 = accent 实心白字；agent = 白底 | 对话页唯一的大色块 |
| 表面 | 无静止阴影；毛玻璃只用于导航/Tab/输入条（iOS 惯例） | 浮层（菜单、toast）才有投影 |
| 图标 | 全 SVG 线性 1.4-1.9px，无 emoji | 工具卡用终端/盾牌小图标 |
| 动效 | 气泡 rise-in 0.22s、运行中状态点呼吸 2.4s、`prefers-reduced-motion` 全关 | |

## 2. 页面结构

| 位置 | 内容 | 说明 |
|---|---|---|
| 左上角 | **环境切换器**（品牌标 + 当前环境名 + ⌄） | 下拉：全部环境 / 各机器（含在线状态与 agent 数，✓ 标当前），切换即过滤主列表 |
| 右上角「+」 | 深色下拉气泡 | **刷新** / 扫一扫配对 / 添加环境 / 通知设置 |
| 主列表 | Agent 列表 | 头像（淡底色 + 首字母 + 状态点角标）、名称、环境 tag、最后一条消息、时间、未读角标；待审批行文案为琥珀色 |
| 列表 meta 行 | 标签 / 备注 / 属性 | 按「列表显示」开关逐项展示：tags 胶囊、note 单行、props 键值（如 model opus-4.5）；超出宽度自动截断，属性最多 1-2 项 |
| 列表显示面板 | 底部 sheet | 四个开关：所属环境 / 标签 / 备注 / 属性；改完立即生效并记住（localStorage），「恢复默认」一键回默认 |
| 对话页 | 右滑进入 | 我方绿气泡（accent）、agent 白气泡、工具调用卡（mono 命令块）、**审批卡（拒绝/同意）**、typing 三点 |
| 底部 Tab | Agents / Sessions / 环境 / 我 | Agents tab 带未读角标；环境页 = 已配对机器 + 添加入口 |

## 3. 交互点（原型已实现）

- 点左上角 → 环境下拉，✓ 标当前项；切到具体环境过滤主列表，空环境有占位态
- 点「+」→ 刷新：转圈 0.9s → 列表时间变「刚刚」→ toast「已刷新 · 5 个 agent」
- 点列表项 → 对话页右滑进入；返回键带所属环境名；返回同时清未读角标
- 审批卡「同意」→ 卡片转绿「已批准 · 命令已在 MacBook Pro 执行」，列表行同步改「运行中」
- 审批卡「拒绝」→ 卡片转红「已拒绝 · 等你的替代方案」，列表行文案同步
- 发消息 → 用户气泡 → typing → 1.2s 后模拟回复
- Tab 切换；Sessions / 我 为范围占位态
- 「+ → 列表显示」打开底部 sheet，四个开关控制列表 meta：环境标签 / tags / note / props（默认 环境+标签+备注 开，属性关）；切换即时重排列表并持久化
- 属性展示示例：Claude 行 `model opus-4.5`，Codex 行 `model gpt-5.1-codex`；有 tags 时属性只留 1 项避免拥挤

评审深链：`index.html#chat-codex`（直开含审批卡的对话）、`index.html#menu`（直开 + 菜单）、`index.html#sheet`（直开列表显示面板）、`index.html#props`（打开属性展示态）

## 4. 与调研结论的对应关系

| 调研结论 | 原型里的体现 |
|---|---|
| 客户端只是认证过的 RPC 视图，执行在服务端 | 对话页只展示状态与审批，没有本地执行入口 |
| 审批是手机端最高价值动作 | 审批卡在消息流中间，一键同意/拒绝，结果回写列表状态 |
| 环境与路由是独立概念 | 左上角环境切换器独立于 agent 列表；「环境」Tab 管配对 |
| 状态分三档（运行/待审批/离线） | 头像角标点 + 列表文案色 + 对话页副标题 + 呼吸动画 |
| 第一版零自写原生模块、不渲染终端 | 工具调用 = 结构化卡片，不显示终端 |

## 4.1 数据模型对齐（真实字段）

| 原型字段 | Snorkeling 真实来源 |
|---|---|
| `tags[]` | `pkg/agentdata` 的 `NoteAndTags` / `TagPatch`（`ai_session_tags`） |
| `note` | 同上，会话级 note（人写的一段备注） |
| `props[k,v]` | `PropPatch`（`ai_session_props`，类型有 text / select 等，如 emoji、priority） |

原型里只放 `model` / `branch` / `cwd` 三个示例键，实际应直出会话 props 的前 N 个。

## 6. 待拍板

1. 「+」菜单要不要加「新建会话」（对应微信「发起群聊」= 新建 agent 会话）
2. 审批卡要不要「本会话始终允许」，还是只保留单次批准（安全默认：单次）
3. 列表头要不要一个「需要你」过滤入口（待审批聚合视图）

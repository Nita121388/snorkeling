Blocks 组（Tab 化 Block）右上角「＋」新建菜单

结构逐字段镜像真实 frontend/app/block/block.tsx（InlineTabBlock / InlineTabLabel）+ block.scss（.inline-tab-block-*）， 菜单数据源镜像 pkg/wconfig/defaultconfig/widgets.json（与右侧 WidgetsBar 同一份注册表）。

新增点仅两处：① tab 行拆为「tabs 滚动区 + 右侧固定区」，「＋」钉死在组右上角，tabs 横向溢出滚动时不动； ② 点击弹出 widget 驱动的菜单 —— Terminal / Agent / Files 三项继承激活 tab 的 connection/cmd:cwd，其余 widget 用自身 blockdef 直通创建。 action 型 widget（commontext，无 blockdef）本期跳过。

场景 1 · 常规（3 tabs）— 点右上角「＋」试菜单
场景 2 · tabs 溢出横向滚动 — 「＋」仍钉死右上角（拖 tabs 滚动验证）
ⓘ 真实实现中滚动发生在 .inline-tab-block-tabs（flex:1, overflow-x:auto）内部， 「＋」位于其右侧的固定 cell —— 无论滚到哪，「＋」都不动、不挨着最后一个 tab。
设计要点
  • 显示条件：仅 blockIds.length > 1 的组显示；preview 预览态 / ephemeral 节点不显示。单 block 节点本期不做。
  • 菜单 = widget 注册表：fullConfig.widgets → workspace 过滤 → display:order 排序。用户自定义 widget 自动出现，零额外代码。
  • 仅三项特判继承：从激活 tab 读 meta.connection + meta["cmd:cwd"] （复用 extractTerminalContextMeta）；拿不到则落本地 home（与 Workspace Home 启动一致）。
  • 创建即入组：CreateBlock 后走现成 layoutModel.addBlockToInlineTab(nodeId, blockId) —— 追加到组尾并自动激活聚焦，零新布局代码。
  • magnified 时可用：往组里加 tab 无害，按钮不隐藏。

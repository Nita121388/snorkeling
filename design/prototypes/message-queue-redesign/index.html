Old vs New — Message Queue

❌ Old: Text-only count

Only a tiny 11px text line: "N messages queued — waiting for the current turn". Invisible in the UI. No per-item cancel, reorder, or priority.

Queue: plain useRef<ChatRequestBody[]> with push/shift. No IDs, no metadata, no operations.

Abort: queuedMessagesRef.current = [] — all messages silently discarded, user must re-type.

✅ New: Interactive QueuePill

Collapsed: badge shows count + high/normal breakdown. Click to expand list. ⌘⇧Q shortcut.

Expanded: scrollable list with drag-reorder, per-item cancel (×), promote (⚡). Index badge shows execution order.

Priority: high (⚡ retry / user promote) inserts before normal. Drain scheduler: 300ms delay on turn_end.

Abort: retains queued messages, shows undo toast with Restore/Dismiss. No silent discard.

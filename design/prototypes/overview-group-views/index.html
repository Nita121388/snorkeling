Overview 分组视图：目录 / 标签

在现有「状态 / Tab / Provider」之外加两种口径。目录按会话 projectPath 的 basename 分列， 标签按会话 tags 的并集分列。两种都不补空列，且「无项目 / 无标签」永远排最后（虚线框标识兜底列）。

目录视图 本次新增

  • 列 = basename(projectPath)；同一项目跨 Tab 聚合（跨 Tab 才是看板的意义）。
  • 列序：卡片数降序 → 标题升序。无项目列永远最后（与 provider 的 fallback 规则同源）。
  • 不补空列：没有会话的项目不占屏。
  • 卡片上的项目 chip 在此视图下可以省掉（列头已经说明）。

标签视图 本次新增

  • 列 = 当前筛选结果里所有 tags 的并集，按字母序；无标签列最后。
  • 一张卡可出现在多列（多标签）。所以「各列计数之和 = 卡片数」这条旧断言在标签视图下不成立， 必须改成 之和 ≥ 卡片数。
  • 重复出现的卡片带 DUP 标记（只在多标签卡上），并在列头 tooltip 说明。
  • 标签数很多时（> 12），列头右侧出现「更多标签」折叠入口（本原型未实现，见下方边界）。

与现有两种口径的一致性

  • 四种口径共享同一份筛选结果（Agents / Opened Tabs），只换分桶规则。
  • 只有 status 分组常显 5 列（含空列）并带状态色点；其余三种只渲染有卡的列、无 tone。
  • 持久化走同一个 overviewBoardGroupAtom；旧版本读到 project / tags 会回落 status。

边界（本次不做）

  • 不做「标签列折叠 / 只显示 Top N 标签」——先看实际标签量再定。
  • 不做按目录层级树（只取 basename，不做 a/b/c 逐层）。
  • 不做跨列拖拽改标签 / 改项目。

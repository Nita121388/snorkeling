①

Skill conflicts —— 同名 skill 装了两份

结论：正常去重，忽略即可，不冲突不报错。

同一套 GitNexus skill 同时存在两份——一份在项目里，一份在你的用户全局目录。pi 的策略是 auto（项目优先）：项目那份生效（✓），用户那份被跳过（✗）。

项目级 生效 ✓
E:\code\snorkeling\.agents\skills\gitnexus\…
用户级 被跳过 ✗
~\.agents\skills\gitnexus-… 即 C:\Users\chemclin\.agents\skills\…
长期隐患 · 为什么值得顺手清理

这两份是同名 skill 的重复副本。若它们内容不一致，容易造成「改了全局那份却没生效」的困惑（因为项目那份优先级更高）。建议二选一保留，删掉不用的那份。

②

YAML 解析报错 —— snorkeling-release\SKILL.md 的唯一真问题

结论：description 值未加引号，含 流程: 冒号子串被当成嵌套映射，导致该 skill 加载失败/元信息识别异常。

报错原文
Nested mappings are not allowed in compact mappings at line 2, column 14
SKILL.md · frontmatter（第 2 行） 
1 ---
2 description: 发布 Snorkeling (WaveTerm fork) 新版本。用于用户提到"发布新版本/…"。流程: bump package.json prerelease 号 → …
3 ---
■ 流程: （冒号 + 空格）是罪魁祸首 —— YAML 把它当成想再开一层的嵌套映射

为什么报错

  1. description: 的值是一个超长未加引号的裸字符串。
  2. 字符串中间混入 流程: （冒号+空格）这类子串。
  3. YAML 解析器把 流程: 视作新的 key: value 嵌套映射。
  4. 但当前是紧凑映射上下文、又无正确缩进，于是抛 Nested mappings 错误。
  5. 后果：frontmatter 未正确解析，skill 加载失败或 name/description 识别异常。

修复方式（任选其一）

❌ 现在（裸字符串）
description: …用于用户提到"发布…"。流程: bump …
✅ 修复 · 单引号包裹
description: '…用于用户提到"发布…"。流程: bump …'

用单引号最稳：值里含中文双引号 "" 与 ASCII "，单引号可整体包裹不转义；也可改用 YAML 块标量 |-。

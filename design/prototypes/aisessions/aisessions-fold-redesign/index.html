会话详情 · 折叠重设计

当前详情里两类聚合元素的可见度都不够：连续工具合并成「工具 ×N」后只是一条 hover 才显箭头的小字； 子代理调用则直接复用普通工具行，没有身份区分，匹配不上时还会退化消失。本原型给出两种 明显、可扫读、可一键展开的折叠卡方案。

A 工具数量折叠 → 工具折叠卡

把「连续 N 个工具调用」从一行淡文字升级成带左 rail、计数徽标、始终可见 chevron 的卡片。 折叠态即可扫读到「做了几件事、各是什么」，展开态逐条可点。

现状（复刻）

  • 纯文字行，chevron 仅 hover 出现
  • 无计数徽标，N 混在自然语言里
  • 折叠 / 展开无层级缩进
  • diff 统计（+N/-M）弱存在感

提议改进

  • 左 rail 色条一眼区分「工具块」
  • 计数徽标 N 独立成视觉锚点
  • 始终可见 chevron + 右侧「展开 / 折叠」hint
  • 展开用 grid-rows 平滑展开，单条可 hover

B 子代理调用 → 子代理折叠卡

子代理用紫色身份色与工具绿彻底区分，头部带 agent 头像 + 名称 + 任务摘要 + 状态点 + 独立打开入口。展开后走左侧紫色导轨，内联渲染子会话内容，孙代理再嵌套一层。

现状（复刻）

  • 复用 ToolCallRow，长得和工具一样
  • 名称写死 subagent，无 agent 身份
  • 匹配失败直接降级为普通工具行
  • 「它派了个子代理」毫无存在感

提议改进

  • 紫色左 rail + 头像强身份区分
  • 头部直接显示 agent 名 · 任务
  • 状态点：完成 / 工作中 / 失败
  • 内置「打开子会话」按钮
  • ambiguous 不改写，列出候选

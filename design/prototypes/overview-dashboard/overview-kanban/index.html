Overview 看板优化 — 原型对比

将 SessionOverview 从列表式布局改造为更贴近看板的形态。建议先对比四套方案，选定后再细化交互并落地到 React 组件。

A. Tab 列（最保守）

低改动

每个 Tab 变成一列。几乎保留现有“按 Tab 分组”的心智模型，只是从垂直列表切换到横向列。

  • 最容易迁移现有数据结构
  • 保留 Tab 名称、顺序
  • 仍能清晰区分“哪个窗口/Tab 的会话”
预览原型 A →

B. 状态列（最像看板）

中高改动

跨 Tab 聚合，按 Agent 状态划分列：Running、Waiting、Needs attention、Done、Idle。更符合“看板一眼掌握全局进展”的诉求。

  • 一眼识别阻塞点（Needs attention）
  • 更适合同时跑多个 Agent 的场景
  • 弱化 Tab 边界，强化“任务状态”
预览原型 B →

C. 混合泳道（最平衡）

中等改动

以 Tab 为泳道（Lane），泳道内再按状态分区或直接用看板卡片排布。既能知道“归属”，又能感知“进展”。

  • 兼顾组织归属和执行状态
  • 减少从 Tab 到状态的认知切换
  • 对现有过滤（Opened Tabs/Agents）也较友好
预览原型 C →

D. Linear 风格（最现代）

中高改动

极简卡片，弱化“块列表”感。突出状态、消息预览、会话备注，操作收纳到 hover。更接近 Linear 的 Issue Board 体验。

  • 最高的可扫视性（信息层级更克制）
  • 卡片更像“任务卡”而不是“块条目”
  • 视觉更现代，适合长时间使用

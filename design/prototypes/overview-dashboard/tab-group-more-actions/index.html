怎么玩

  1. 列表视图现在是两段：上面「打开的 Tab」（默认展开），下面「更多 Tab」一行入口（默认折叠）。
  2. 右键「打开的」区任意组头 → 收藏到「更多」：该组立刻掉进「更多」区，Tab 栏同步收进 ⋯。
  3. 点「更多 Tab」入口行 → 展开，里面分 ★ 收藏 / 未打开 两类。
  4. 菜单里「查看「更多」区」→ 自动展开该分区并闪烁高亮目标 Tab。
  5. 看板切「按 Tab」后列头右键 → 同一份菜单；时间轴无 Tab 维度。
  6. 右上角旧的「本次打开的 Tab」过滤按钮已取消 —— 它的职责被「更多」分区（默认折叠）接管。

本次新增点

  • ① 列表组头右键菜单（打开 Tab / 收藏 / 查看「更多」区 / 重命名 / 复制 ID / 关闭）。
  • ② Tab 栏「更多」下拉新增「★ 已收藏」分区。
  • ③ 收藏 = 收起 + 星标：Tab 栏与 Overview 两个面用同一个意图。
  • ④ 组头状态徽标：★ 已收藏 / 未打开。
  • ⑤ 看板「按 Tab」列头接同一菜单 builder。
  • ⑥ 分区模型：打开区 / 更多区，替代旧的「本次打开的 Tab」过滤按钮。

为什么旧过滤按钮有问题

旧语义：一刀切隐藏
hideUnopenedTabs 打开后，所有「本次启动未打开」的组直接从 DOM 消失，没有入口、没有计数，用户不知道藏了多少、也回不去。
新语义：折叠成一行入口 + 计数 + 收藏/未打开分项。
两套隐藏体系对不上
Tab 栏用 collapsedTabIds（手动收起 + 未打开），Overview 用 openedThisLaunch（只认本次启动）。同一个 Tab 在两个面命运不同。
新语义：两个面共用「打开 / 更多」两桶，收藏动作双向同步。
「只显示 Agent」还留着吗？
它是视图内过滤（只过滤组内行，不删组），与这次的分区是正交的。
推荐：保留不动。

待你拍板

D1 · 分区归属规则
推荐：starred 或 !openedThisLaunch → 「更多」区；其余 → 「打开」区。收藏优先级最高（打开过也进更多）。
这就是「收藏的 + 更多的 = 默认不展示」。
D2 · 旧过滤按钮怎么处理
A：删除按钮，用「更多」分区默认折叠替代（推荐）。B：保留但改名为「只看打开的」且默认开。
推荐 A —— 用户不用再记一个开关。
D3 · 分区展开状态是否持久
旧 key snorkeling:session-overview:hide-unopened-tabs 可迁移成「更多区是否展开」的初值。
推荐：持久（默认折叠）。
D4 · 收藏存储
A：扩 tab-collapse-store；B：Tab meta tab:starred（走 SetMetaCommand，零新 IPC）。
推荐 B。
D5 · 「查看更多」打开谁
改成展开 Overview 的「更多」分区并高亮（本原型）。
推荐：是。Tab 栏 ⋯ 下拉仍独立存在，不混。

属性行渲染规则（紧凑化）

数据层不动（resolveBoardPropRows 已按类型归一 select/multi/checkbox/text），只改渲染层： 自解释的值不再带属性名前缀，名字降级进 title="name: value"，hover 与无障碍信息不丢。

属性类型 现状渲染 方案渲染 规则
status / select 单值 名字 + 色胶囊：Status In Progress 仅色胶囊：In Progress 有色胶囊自解释（Notion 9 色板，固定浅色，不随主题变）
单 emoji 文本（`emoji` 属性） emoji 🦊（与左上头像同一 emoji 并排） 整条不渲染（左上头像已表达同一信息） 与头像重复（2026-11-22 截图确认）
person / multi_select 名字 + chips 仅 chips chips 自解释
text / number / url 名字 + 值 不变 纯文本值不自解释
checkbox 名字 + ✓ 不变 值只有 ✓

卡面层次

问题 1「卡与面板融为一体」：现状 background: transparent，卡片与 --panel-bg-color 同色， 只靠 1px --border-color（白 16%/暗）撑轮廓。方案给卡一个真实表面层：暗色 --surface-strong-color（白 8% 叠面板）/ 亮色 --surface-color（#fffdf8），配 --surface-shadow-color 的微阴影；hover 抬 1px + accent 38% 描边 + 阴影加深。

问题 2「卡内缺乏层次」：现状 head / meta / preview / note / props / metrics 六行同权重平铺（gap: 6px， 字号 9–12px 混排）。方案分四段： ① 头部（头像 18→20px + 标题 600/12px + age）→ ② 状态/meta（chip 一族，16px 高/9–10px）→ ③ 正文（preview + note + 属性行，统一 secondary）→ ④ 脚注（度量轨 + mini timeline）。

注意：.session-metrics 本身已有 border-top: main/8% + padding-top: 6px， 所以「度量上分割线」不是新增项，方案重点是把这条线之上的层级拉开（正文分组、行距、字重），而不是再画一条线。

变体 B 状态左轨：滚动后列头不可见，左轨让单卡自证状态。代价是与卡头状态 chip 双通道重复、窄列压缩内容 —— 推荐先落 A。

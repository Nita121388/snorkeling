口径假设（未拍板项，按推荐值先落）

这三条决定实现形态，改起来便宜但要先说清楚。

① 「会话数量」= 该会话的消息条数（SessionSummary.messageCount），不是"某 agent 名下 N 个会话"的聚合卡。
② 「运行时长」= 活跃跨度（createdAt → updatedAt，live 走到 now）。 不是 Σ working 段 —— 实现前核对发现真实数据里没有 per-block 状态历史 （buildTimelineSegments 的 history 参数无调用方），Σworking 会退化成 chip 的跑时或恒 0。
③ 落点 = 看板卡 + 列表行都上，两处复用同一个 <SessionMetrics> 组件与同一份阈值表。

一张卡上的三个「多久」（语义必须可分辨）

卡头 age / 状态 chip / 度量轨三个时长挨得很近，且前两个单位都是 m —— 不标注就会互相冒充。

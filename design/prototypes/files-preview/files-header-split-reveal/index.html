Files Block Header · 锁存式分区（进入即锁，离开恢复）

规则：进入 header 那一刻按进入点决定方向（左半 / 右半）→ 整个 hover 会话内锁死，鼠标在 header 里怎么移动都不翻区。
离开 header → 宽限 N 毫秒后恢复 NEUTRAL；再次进入才重新判定方向。 所以"右组向左伸过中线"完全无害 —— 根本不会重新判定。

状态机

3 个状态 + 1 个定时器
NEUTRAL
两侧都不展开，路径完整显示。
pointerenter → 按进入点 x 判定方向（x < 中线 → LEFT，否则 RIGHT）→ 锁存
LATCHED_LEFT
左组展开，右侧不动。header 内任何 pointermove 都不改变状态。
pointerleave → 启动 resetTimer(graceMs)
LATCHED_RIGHT
右组展开 + 左侧让位（chevron + 路径收起，只留类型图标），腾出的宽度全给右组。pointermove 不改变状态。
pointerleave → 启动 resetTimer(graceMs)
GRACE（宽限中）
鼠标已离开 header，但方向仍保持。
宽限内 pointerenter → 取消定时器，沿用原方向（不重新判定）
定时器到期 → NEUTRAL
FROZEN（冻结）
溢出菜单 / 浮层打开时 pointerleave 不启动定时器，状态永久保持；
关闭菜单（点击外侧 / Esc）→ NEUTRAL
实现级保证：状态转移只由 pointerenter / pointerleave 驱动，pointermove 完全不参与判定。 这就是"进去之后随便怎么晃都不会翻区"的来源，不依赖任何几何优先级判断。

自动验证

合成 pointer 事件走真实状态机 · 三项断言
— — —
断言：①全程 zone 恒定（不出现翻区）②宽限内重新 pointerenter 后方向不变 ③超过宽限后从另一侧进入方向必须切换。三项同时 PASS 才算锁存语义正确。

三种分区算法对比

算法header 内翻区风险
中线实时切分每次 pointermove 重算 必然自激：右组越中线 → 翻 left → 右组消失 → 点不到
保持区 + 触发带不翻（落在 icon 上命中保持区） 逻辑复杂：4 个矩形 + 优先级 + 空档宽限，边界多；鼠标停在 icon 间隙仍可能抖
锁存（本方案）永不，pointermove 不参与 最简：3 状态 + 1 定时器，零几何判定，可纯函数单测
唯一代价：想从左侧换到右侧，必须先移出 header、等过宽限、再从另一侧进入。这符合直觉（与菜单/工具条"离开即关"一致）， 且比"晃过去就换"更可预测。宽限可配（默认 400ms，拖到 0 即"离开立刻恢复"）。

交互契约

项约定
锁存（核心）方向只在 pointerenter 判定一次，之后整个 hover 会话内不可变。pointermove 不参与分区判定。
恢复条件pointerleave 启动 resetTimer(graceMs)（默认 400ms）→ 到期回 NEUTRAL。宽限内 pointerenter → 取消定时器并沿用原方向。
切换方向必须"离开 header → 等过宽限 → 从另一侧进入"。不提供 header 内直接切换。
菜单 / 浮层打开期间 FROZEN：pointerleave 不启动定时器；菜单自身 pointerenter 也算仍在会话内。关闭后回 NEUTRAL。
左侧让位LATCHED_RIGHT 时 chevron + 路径收起，只留类型图标；腾出宽度全给右组。tier 0 且右组本就放得下时不让位。
… 永不削尾ellipsis 自身 neverOverflow，否则整条逃生通道消失。
pinned 让位< 192px 时 Refresh / Edit 进溢出；Close 一直在 header。< 88px Close 进浮层。
键盘焦点进入 header 任一按钮时两组全展开（不依赖鼠标锁存）；Tab = header → 溢出菜单 → 浮层。
回退block:header-split-reveal / block:header-yield-left / block:header-narrow-tier / block:header-hover-latch + block:header-hover-grace（数值），默认 on / 400ms。

落地要点

  • 状态机纯函数：reduce(state, event)，事件仅 ENTER(x) / LEAVE() / RESET() / FREEZE() / UNFREEZE()。零 DOM 依赖，可直接单测全部转移。
  • 单一定时器：resetTimer；FREEZE 时取消并不再启动。用 pointerenter/leave 而非 mouseenter/leave（兼容触控笔）。
  • 进入点中线取 pointerenter 时刻的 header getBoundingClientRect()（此时未让位，中线稳定）。
  • 不动 isHovered：它与 claimInfoCard / Agent·Note 悬浮卡共用。锁存状态独立成 hoverLatch。
  • 单测判据：①ENTER 后连续 100 个任意 x 的 move，state 不变 ②LEAVE 后 graceMs-1 内 ENTER → 方向不变 ③LEAVE 后 graceMs+1 → NEUTRAL，再 ENTER 另一侧 → 切换。
  • 分配不变量：plan(w, zone) → {shown, hidden}，shown.length + hidden.length === total，w ∈ [40..900] step 2 全跑。
  • 像素验证：scripts/verify/ 断言「header 内每个可见 .ibtn 的 rect 完全落在 header 矩形内」（禁止硬切）。
  • 影响面：blockframe-header.tsx 是全 block 共用 header；term 走 useTermHeader 分支需确认；aisessions 自定义 endIconButtons 需检查 priority 默认值。

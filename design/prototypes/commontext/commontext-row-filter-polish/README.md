# Common Text · 列表行高修复 + 筛选区单行化

浏览器直接打开 `index.html`（无构建、无依赖；图标走 CDN，离线时只是缺字形，不影响布局判断）。

外壳上的开关只用于对照，不是产品 UI：

| 开关 | 作用 |
|---|---|
| 行高 `44 / 52 / 64` | `44` = **现状复现**（带标签的行被 `overflow:hidden` 裁掉下半截）；`52` = 建议（两行）；`64` = 备选（三行） |
| 宽度 `宽 900+ / 窄 700` | 看筛选行在窄列下的折行方案 |
| 显示标注 | 展开底部拍板说明 |

## 要解决的问题

1. **列表行被截断**：真实组件 `ROW_HEIGHT = 44`（`commontext-compose-modal.tsx:73`），行内 `overflow-hidden`，
   而带标签的行实测需要 ≈**62px**：

   | 内容 | 高度 |
   |---|---|
   | 标题行（`text-xs` 12px + 徽标 9.5px） | 16px |
   | 摘要（`text-[11px]`） | 16px |
   | 标签 chips（`text-[11px]` + `py-0.5` + border） | 18px |
   | 行上下 `py-1.5` | 12px |
   | **合计** | **62px** |

   差 18px 正好是整行标签——所以「有些行看起来被切了一半」。

2. **筛选区太占纵向空间**：现状是 4 层（搜索 / 创建者分段 / 排序图标组 / 无标签 + 标签 chips），
   在 44px 行高下等于吃掉 3 行的可视空间，而排序又是 5 个裸图标（含义只在 tooltip 里）。

## 设计结论（待拍板）

### A. 行 = 固定 52px 两行（建议）

```
┌ 2px ┬ 16 ┬───────────────────────────────────────┬ 58px ─┐
│ pin │ 标题（truncate）· 同步点      创建者徽章 │ 次数   │
│     │ 摘要（truncate）        #tag #tag +2     │ ▁ 1h   │
└─────┴──────────────────────────────────────────┴────────┘
   行内 padding 8/8 → 内高 36（16 + 18 + 2 余量）
   ↑ 创建者徽章居右（不在标题后面），右缘与 meta 列同一条竖线
```

- **创建者徽章居右**（2026-11-21 用户定）：标题独占左侧宽度；徽章 `margin-left:auto` 贴行内右缘。
  原来徽章跟标题后面，位置随标题长度漂移，跨行扫「谁创建的」对不齐；靠右后所有徽章右缘对齐。
  同步点（pending 小圆点）仍紧贴在标题文字末尾——它描述的是「这一条」，属于标题的一部分。

- **标签并入第二行**（摘要 `flex:1` 截断，标签 `max-width:52%` 截断，最多 3 颗 + `+N`）：
  行高固定、虚拟化常量不动（`ROW_HEIGHT` 与 spacer 数学仍是单一常数）。
- 无标签的行第二行只有摘要，视觉不空（摘要本来就长）。
- 标题仍单行截断（长标题用例在第 6 行）。

### B. 行 = 固定 64px 三行（备选）

标签独占第三行，`flex-col`。代价：列表可视行数少约 20%。
**只在「标签必须一眼看全」的场景值得**；默认建议 A。

### C. 筛选区收敛成一行

```
[ All 7 | 👤 4 | 🤖 3 ]  [💻 Workstation ▾]  [⇅ 最近使用 ▾]  [▢ 无标签 2]  [#客户 #sql #报表 …]  [✕]
```

- 所有控件同高 **26px**、同圆角、同 6px 间距（现状是 22px 分段 + 22px 原生 select + 24px 图标组，三种节奏）。
- 创建者三档：**同一壳**、内部靠底色分隔，不再每颗 chip 各自描边（现在 `border` 在组上，视觉已经接近，原型再收一档）。
- 机器筛选：`fa-computer` + 当前机器名 + caret 的 chip（沿用 `AppSelect` 的隐藏原生 select 值通道，验证台口径不变）；
  激活非「任意电脑」时 accent 底色。
- 排序：从 5 个裸图标改成 **显示当前排序名的 chip + 菜单**（`⇅ 最近使用 ▾`）。icon-only 在窄列里没法学，且现状
  在搜索态还会整组置灰——换成菜单后「为什么点不动」用 disabled 项 + 说明文案表达。
- 标签条：单行横向滚动 + 右缘 mask 渐隐，不再换行成两排把「无标签」挤走。
- 有筛选生效时右侧出现 `✕` 清空（不是常驻）。
- **窄态（< ~700px）**：筛选行折两行——「创建者 + 机器」/「排序 + 无标签 + 标签条（独占整行）」。

| `scripts/verify/commontext-*` | 行高断言从 `44 ± 容差` 改为 `52 ± 容差`；新增「标签行未被裁切」判据（行 `scrollHeight <= clientHeight`）与「筛选行单行不换行」判据 |

## 判据（落地后必须可机器判定）

- 带 0 / 1 / 4 颗标签的行，`row.scrollHeight === row.clientHeight`（无裁切）且三档行高一致。
- 列表容器 `data-commontext-window` 与 spacer 高度仍按 `ROW_HEIGHT` 线性推进（滚动到第 300 行位置正确）。
- 筛选区在 900px 宽下 `getBoundingClientRect().height <= 30`（单行）；在 620px 宽下不超过 2 行。
- 机器筛选选中后行数收敛且 `data-commontext-device` 值通道同步（沿用现有验证台断言）。

## 被否的选项（备查）

- **D. 保持 44px，行内干脆不显示标签**：行高不用改，但「这条属于哪些标签」变成隐藏信息，
  要逐条点进详情才能看到；用户当前的使用习惯就是靠标签扫视，等于砍功能。否。
- **E. 变高行（按内容测量 + 估算器）**：能同时做到「两行/三行自适应」，但虚拟化要引入行高
  测量缓存 + 滚动锚定修正（`data-commontext-window` 与 spacer 数学全部重写），
  与本包「修观感」的量级不匹配。若日后标签数量分布极端（20+），再单独立包做。
- **F. 筛选区收进「筛选」弹出面板**：纵向最省，但常用筛选（创建者 / 机器）每次都要多点一次，
  高频操作变两步。否，保留常显一行 + 折叠只留给低频项（标签条滚动即可）。

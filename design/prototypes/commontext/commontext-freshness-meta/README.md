# CommonText：更新时间可视化（不显示具体时间）

浏览器直接打开 `index.html`，无构建、无依赖（字体与图标走 CDN，离线也能用，只是字体回退）。

需求：列表右槽的「4h ago / 2d ago」在扫视时要逐个读字，希望换成图形编码，不显示具体时间。

---

## 这版做了什么

镜像真实双栏结构（900×620），只改一处：把列表右槽第二行的
`<i class="fa-regular fa-clock"> 4h ago` 换成图形。行高、`w-[58px]` 槽宽、hover 淡出逻辑全部照抄真实实现。

给了五个候选（A 条 / B 信号格 / C 点 / D 纯色方块 / E 热力方块）+ 一个档位标定实验台：

| 开关 | 选项 |
|---|---|
| 列表右槽 · 更新时间 | 现状（文字）/ A 连续条 / B 信号格 / C 色点 / **D 纯色方块** / **E 热力方块** |
| A 档位标定 | 现有 100/62/32/15/6 / 提议 A 100/68/44/26/12 / 提议 B 4 档 |
| 详情页脚 · 更新时间 | 现状（相对时间）/ meter + 档位词 / 精确时间戳 |
| 排序 | Recently updated（默认）/ used / usage / created |
| Hover 提示 | 关掉后可看纯图形效果 |

URL 直接锁定某个组合，方便贴给别人看同一屏：

```
index.html#list=heat&detail=meter
index.html#list=bar&detail=meter&scale=tuned
index.html#list=sq&detail=stamp&hint=0
```

`scale` 只在 `list=bar` 下有意义。

## 原型里看到的四条结论

这四条是纸面推演不出来的，只有真画到 26px / 12px 才看见：

**1. C（纯色点）信息量基本为零 → 排除。**
6px 圆点的 5 个色阶在暗色主题里全挤在 grey-green 一段，邻档靠猜。只有颜色一个通道，
色弱用户完全失效。

**2. B（5 段信号格）的「可数」优势在 1× 下不成立 → 不推荐。**
4px 段 + 1px 缝，在 10px 字号的行里糊成一条虚线，数不出 5 还是 4。要真可数，槽宽得从
26px 加到 36px 左右，会挤占标题列；而且换成「段数」编码的代价是跟 aisessions 变成
**两套时间语言**。

**2.5 把点换成方块，颜色才够用；但纯色方块仍分不开 4/5 档。**
面积从 6px² 到 10-12px² 之后明度差终于看得出来，所以 **D 纯色方块**比 C 好一个量级。
但它还是只有颜色一个通道 —— 「4 档 = 12 天」和「5 档 = 45 天」在暗色主题下几乎同灰
（见下方对照表 D 行），实际退化成 4 档制。

**3. A（连续条）可用，但现有比例表需要重新标定。**
`RecencyFillByLevel = ["100%","62%","32%","15%","6%"]` 是照 aisessions 行宽标的。
搬到 26px 槽后：4 档 = 3.9px、5 档 = 1.6px —— **「一周内改过」和「一个月没动」分不开**。
aisessions 那句注释（「26px 宽满格 vs 一成一眼就能区分」）只在 1 档 vs 5 档时成立。

## 推荐：E 热力方块（颜色 + 填充高度双通道）

形状上是方块，语义上是 `<HeatCell>`—— 这个原语已经在 aisessions 列表里用过，
**两个通道同向变化**：1 档满格 + 满浓度，5 档只剩一格底、色相也退到 muted。

| 档位 | 阈值 | 填充高度 | 填充色 / 浓度 |
|---|---|---|---|
| 1 | < 1 小时 | 100% | accent · 100% |
| 2 | < 1 天 | 82% | accent · 84% |
| 3 | < 7 天 | 64% | accent · 70% |
| 4 | < 30 天 | 46% | muted · 58% |
| 5 | ≥ 30 天 | 28% | muted · 48% |
| — | 从未编辑 | 0%（空槽） | — |

尺寸：槽 12×12、圆角 3px、槽底 `--surface-strong`；内部填充满宽、底部对齐。
右槽 `w-[58px] h-7` 里放得下：使用次数 ~11px + 间距 3px + 方块 12px ≈ 26px。

三条理由：
- **双通道**是唯一在 1× 下还能分开 5 档的方案（对照表里只有 E 行的 4 档/5 档肉眼可分）。
- 复用已有原语，不是新发明一套视觉语言 —— `HeatCell` 在 aisessions 已跑过一轮评审。
- 方块读起来像「一个物」，不像 26×5 条形那样容易被误读成「完成度 / 进度」。

代价：比条形高 7px，右槽两行合计 ~26px，刚好贴住 `h-7` 上限，没有余量。
若后续要在右槽再加一行，方块得缩到 10×10（填充高度差会变紧，但还够用）。

### 备选：A 连续条 + 合并成 4 档

如果更看重「与 aisessions 列表完全一致」，那就用 A，但必须同时把比例重新标定或砍到 4 档，
否则 4/5 档在 26px 里是白给的：

既然 26px 里 4/5 档本来就分不开，与其重新标定去硬撑 5 档，不如**把「分不开」变成设计决定**：

| 档位 | 阈值 | 条长 |
|---|---|---|
| 1 | < 1 小时 | 100% |
| 2 | < 1 天 | 66% |
| 3 | < 7 天 | 33% |
| 4 | ≥ 7 天 | 12% |
| — | 从未编辑 | 0%（只留槽） |

理由：26px 里 4 档的填充差（100/66/33/12）每档都 ≥ 8px，1× 下可分辨；
且「一周前改的」和「半年前改的」在 CommonText 这个用途下没有区别 —— 都是「不新鲜」。

代价：CommonText 用 4 档 = 同一 app 两种颗粒度（aisessions 是 5 档）。
原型里用「A 档位标定」开关切换 `现有 / 提议 A / 提议 B`。

## 规格（三个变体共用）

- **槽必须可见**：1 档只填 12% 时若没有槽底，图形等于消失。用比行底色差一档的
  `--surface-strong` 当槽，不用 `border` 描边（同 `HeatCell` 的判断：描边会让填充看起来像
  「被框住的窗口」）。
- **精确值只走 tooltip**：`Updated 4h ago · 03-15 09:34`。真实代码里 `metaTooltip` 已拼好，直接复用。
- **无障碍**：`role="img"` + `aria-label="Updated 4h ago"`，不要只给 `title`（对读屏不稳）。
- **刷新时机**：4 档跨越以小时/天为单位，不需要定时器；但弹窗 `onOpen` 时要重算一次 `now`，
  否则「1 分钟前改的」第二天打开还显示满格。
- **「从未编辑过」是新增语义**：文字版区分不出来（显示 40d ago），图形版用「空槽」一眼可见 ——
  这类条目其实最稳定，值得优先复用。

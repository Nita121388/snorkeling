09 · 常用文本 CommonText

镜像源 frontend/app/commontext/ — 置顶与使用元信息、搜索即过滤、属性紧凑两列、标签分离语义、发送目标。

现状问题
P1
高频条目与低频混排。 没有「置顶 + 使用次数/最后使用」元信息，最常用的那条永远靠运气找。
P2
搜索是按钮不是过滤器。 输入后要点「搜索」才生效，没有 ⌘K 全局唤起。
P3
compose 属性单列六行。 常用文本 90% 只填标题+内容，属性占满首屏把正文挤走。
P4
标签与正文语义混写。 历史版本 run deploy #urgent #ops 把 # 标签当正文存（已修，但输入侧仍需 chip 化提示）。
优化方案
S1
置顶组 + 使用元信息。 行尾显示「×42 · 3h ago」；置顶组永远置顶，右键可固定/取消。
S2
搜索即过滤 + ⌘K。 输入即时过滤标题/正文/标签；空态给「新建这条」快捷动作。
S3
属性紧凑两列网格。 标题/快捷键/类型/来源两行放下；正文区域始终可见 ≥ 80px。
S4
标签 chip 分离 + 发送目标内联。 标签独立输入（chip 化，回车成 chip 不进正文）；底部内联目标选择（当前 Tab / Agent），后台发送带 toast 回执。

搜索 100ms 防抖即时过滤；命中字段高亮；⌘K 全局。
compose 属性两列（label 84px）· 正文 ≥ 80px 常显 · 标签 chip 不进正文。
发送 目标内联在底部（非弹层）；发送后 toast 5s 可撤销。

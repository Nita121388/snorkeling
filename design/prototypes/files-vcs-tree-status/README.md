## 需求（用户截图 + 补充）

1. `projects` 下每个子文件夹是**独立仓库** → 想知道各项目文件夹是干净还是有变更
2. `i-am-cooking` 内 `.trellis` / `docs` / `scripts` / `tests` 是**同仓库子目录** → 想看出变更集中在哪
3. 补充要求：**改变文件 icon 颜色** 的方案

**硬约束：一切以不影响性能为前提。**

## 四方案对比（原型可切换实测）

| 方案 | 表现 | 判断 |
|---|---|---|
| **A 行尾圆点** | 行尾 `●`，脏=橙+数字 / 干净=绿点 | 能用，但只有两态，分不出 M/U/D；干净也标绿点会满屏点 |
| **B 图标整体变色** | 文件夹/文件 icon 换色 | ❌ **不推荐，见下方原理** |
| **C 图标变色 + 圆点** | 两者叠加 | 信息最全但双重编码，视觉最吵 |
| **D 文件名着色 + 行尾字母** ★ | 文件名文字变黄/绿/红 + 行尾 `M`/`U`/`D` | ✅ **推荐**，VS Code / JetBrains 做法 |

### 更正：A 方案其实「能」显示哪个文件变了

上一版说「A 看不出改了哪个文件」是**错的**。只要文件行也渲染圆点，就能标出哪个文件脏。
A 的真实短板是**不携带变更类型**（分不出修改/新增/删除），不是不能定位。

## 为什么图标变色显「脏」（设计原理）

1. **icon 颜色本来承载「文件类型」**：文件夹黄、代码蓝、图片紫。按 VCS 状态换色后，
   用户分不清「这是变色了的代码图标」还是「这文件本身是橙色类型」——两套编码抢同一个视觉通道
2. **小面积高饱和色块堆叠**：icon 是 13px 左右实心块，几十行彩色叠加整棵树会花掉、失焦；
   文字是细笔画，同色率下温和得多
3. **作用域不同**：icon 换色只能表达「这个变了」，文字 + 字母能同时表达
   「哪个变了」+「怎么变的」（两个通道）
4. **偏离成熟产品做法**：VS Code / JetBrains 都是文件名**文字**变黄/绿，图标只加 **M/U/D 角标**，
   不整体换 icon 色

## D 方案语义

### 文件行：字母表「变更类型」

| 状态 | 文件名文字 | 行尾 | 变量 |
|---|---|---|---|
| modified | 橙 | `M` | `--warning-color` |
| untracked | 绿 | `U` | `--success-color` |
| deleted | 红 + 删除线 | `D` | `--error-color` |
| **clean** | **不变色** | **无** | — |

### 文件夹行：数字表「变更数量」

| 状态 | 文件夹名 | 行尾 | 变量 |
|---|---|---|---|
| 有变更 | 不变色（不抢类型色） | `2`（该目录下变更文件数） | `--warning-color` |
| clean / 非仓库 | 不变色 | 无 | — |

> **为什么文件行不给数量**：单个文件行就是 1 个变更，数字恒为 1，没有信息量。
> 数量只在**目录聚合**时有意义（该目录下有几个文件变了）。
>
> 若希望更紧凑，可把「文件夹数字」关掉（原型里有开关），只靠字母定位具体文件。

> ⚠️ **干净不要用绿**，否则与 untracked 的绿混淆。干净 = 完全静默，由 Files Header 路径变色单独承担「一眼看出干净」。

## 两类「项目文件夹」

| 类型 | 例子 | 状态含义 | 数据来源 |
|---|---|---|---|
| 子目录是独立仓库 | `projects/agent-prompt-studio` | 仓库整体 clean / dirty | `repositories[]` |
| 仓库内普通子目录 | `i-am-cooking/.trellis` | 该目录下 N 个变更文件 | `status[]` 路径前缀聚合 |

## 性能设计（硬约束）

| 指标 | 预算 |
|---|---|
| RPC 调用次数（整棵树） | **1 次** |
| 每行渲染计算 | **O(1) 查表** |
| status 聚合 | O(M) 一次 |
| D 方案新增 DOM | 仅变更行 +1 `<span>`（字母或数字），其余零新增 |
| 行尾槽位 | `.trail` 固定存在，方案切换不改布局 → 无 reflow |
| 滚动 / hover 新增请求 | **0** |
| 目录切换 debounce | 250 ms |

做法：

1. **一次 RPC 拿全**：`RemoteVcsRepositoriesCommand({ path, scandepth, statuslimit: 2000, includeparent: true })` —— 绝不对每行单独请求
2. **一趟遍历建两套索引**：`Map<目录首段, 变更数>` + `Map<相对路径, 变更码>`，同趟 O(M)
3. **只算可见层级**：只给当前展开层直接子行打标记，不递归整棵树
4. **跳过噪音目录**：`node_modules` / `.git` / `dist` / `target` 不扫描不标记
5. **缓存 + 精准失效**：`directoryVcsStatusCache`（key = conn + dir），仅 VCS 操作成功 / 手动刷新 / 目录变更时失效
6. **虚拟滚动友好**：按行 key 查表，行复用不触发计算

## 语义色修正（重要）

原 Header 方案用 `--accent-color` 表示「干净」，但 4 套主题 accent 实际是：

| 主题 | accent | 是否像「干净」 |
|---|---|---|
| 暗色默认 | 绿 `rgb(88,193,66)` | ✅ |
| 浅色 | 紫 `#9e60c5` | ❌ |
| 极简 | 黑 `#1a1a1a` | ❌ |
| 暖色 | 橙 `#c38057` | ❌ |

**改用 `--success-color`**（4 套均绿系），语义跨主题稳定。
Header 路径变色同步改为 `color-mix(in srgb, var(--success-color) 45%, var(--secondary-text-color))`。

# 块级所见即所得对标（父任务）

## Goal
把「markdown 编辑部分」做成**对标 Wolai、辅以思源与 Milkdown 的块级所见即所得体验**，并做出我们自己的特色（文件优先 + 编辑器与预览零差异 + 本地 Obsidian 资产安全）。
本父任务拥有**源要求集、任务地图、跨子任务验收与最终集成评审**，自身不直接实现。

## 三条第一原则（所有取舍回到这里）
- **R1 尽量 1:1 对标 Wolai**（除「本地文件为主的 Obsidian 模式」兼容降级外）
- **R2 不改主题色**：颜色只从既有主题 token 取；禁止新增颜色字面量与**悬空 token**
- **R3 编辑态 ≡ 预览态（零差异）**：进入编辑不得改变任何结构性样式；唯一允许的视觉 delta 是 caret / selection / hover 可供性。**必须有机制与测试保证，不能靠自觉**

## 追加硬约束（用户明确）
- **每个块类型必须配完整的 UI 测试**（渲染 / 编辑 / 往返 / 样式断言四类）
- 必须**所见即所得**；`[!TYPE]`、`>`、```` ``` ```` 等标记不得在编辑态露出
- 主题色与既有视觉语言不变

## 复用要求（用户明确追加，2026-10-12）

**这条线的最终交付不是"在 Snorkeling 里做好编辑器"，而是"我们自己的 Milkdown"**：一套可被其他项目直接使用的 markdown 编辑内核。

- 必须**1:1 复刻 Wolai/思源/Milkdown 的样式与 UX**（除主题配色外），同时保留我们自己的特色与设计感
- 主题样式**不照抄**：沿用我们的主题系统（R2 不改主题色）
- **首个真实消费者**：`~/Primary/projects/journal`（Chrome 侧边栏扩展：纯 ESM、零框架、无打包器、含 Node host）
  → 因此**内核不得依赖 React**：`md-core` + `md-dom` 必须能被无框架项目直接用，React 只做薄绑定
- 架构与公开 API 见 `方案/Block-Editor 笔记编辑体验升级/11-我们自己的Milkdown-架构与公开API.md`

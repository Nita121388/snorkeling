# 诊断与方案记录（2026-11-20 下午，nita 报障 → 只调查 + 建包，未改代码）

## 用户报障

Overview 看板点 agent 卡片很卡顿，甚至点不开。

## 诊断结论（已复现）

- **主因（点不开）**：`frontend/app/session-overview/overview-board.tsx` `openCardFromTarget` 的
  `event.target !== event.currentTarget` 卫语句。b35075532（2026-11-08，卡片动作按钮）把根/头两层
  onClick 都换成该卫语句 —— 卡片内部全是子 span（标题/头像/年龄/chips/tags/属性/预览/Note/度量），
  点它们时 target ≠ currentTarget，两层全 return。只有卡片裸内边距能开弹窗。
- **复现**：jsdom 渲染 BoardCard 后 dispatch click：标题/预览/头像 → onOpenCard **0 次**；内边距 → 1 次。
  临时用例已删除（骨架在会话里，恢复很快）。CSS 只对隐藏动作区设 pointer-events:none，死区真机成立。
- guard 本意是挡动作按钮冒泡，但按钮已各自 stopPropagation，纯多余。

## 卡顿侧（两个放大器，11-10 修复轮的漏网，另拆包）

1. `columns = groupOverviewCards(...)` 未 memo → `columnKeys` 每渲染换引用 →
   `useLayoutEffect([layoutSignature, columnKeys])` 每渲染重跑 `captureBoardSnapshot`
   （querySelectorAll + 每卡 getAnimations() + getBoundingClientRect），`rebaseline`/ResizeObserver 每渲染重建。
   点击必触发一次面板重渲（markBlockViewed 写 blockViewedAtAtom），这笔 O(n) 采样正好压弹窗入场帧。
2. 15s summary 轮询（`SESSION_SUMMARY_POLL_MS`）→ summaries 换引用 → `boardCards` 全量重算 → 全板重渲；
   30s now tick → `miniTimelines` 全量换引用 → 同样全板重渲。BoardCard memo 挡不住（卡对象/segments 引用都换）。

## 方案（nita 已确认：emoji 区 + 悬浮按钮要独立点开，其余整卡开弹窗）

- 卡片根一个 click 处理器 + 热区白名单：`button, a[href], input, textarea, select,
  [contenteditable="true"], [data-card-interactive]`。target 在热区内（不含根）→ return；
  否则 `stopPropagation()` + `onOpenCard(card)`。删 head 上重复 onClick；动作区 stopCardEvent 保留。
- emoji 头像改 `<button data-card-interactive>` → `openAgentEmojiPicker(blockId, provider, rect, "session", sessionId)`
  （条件 `card.isAgentLike && provider !== ""`，不满足仍渲染纯 span，点它走整卡）。
  `OverviewBoardCard` 需补 `provider` 字段（raw key，取自 `OverviewBlock.agentProvider`；providerLabel 是显示名不能用）。
- 键盘双触发修复：根 keyDown 加 `event.target !== event.currentTarget` 守卫
  （现状在 emoji/动作按钮上按 Enter 会冒泡到根同时开弹窗）。
- 选区保护：`window.getSelection()?.isCollapsed === false` 时不开。
- 性能项（全板重采样 / 周期性重渲）**不混进本包**，另拆。

# 子任务 2：图片块（image-block）

## Goal
图片块做到「Wolai 的可用 + Obsidian 的兼容」，并**先修掉现存的写盘数据事故**。

## 关键事实（来自 08 方案 §2.2 与调研）
- 现状：`markdown-render/image.tsx:84` 用 `parseImageSizeSuffix` 支持自研语法 `![alt](path =300x200)`
- **bug 级**：该语法**写盘后图片不渲染**（用户调过尺寸的图直接消失），且**零单测** ← **数据级事故，P0 最高**
- Wolai：拖拽缩放、可选说明文字、`/tp` 插入
- 方案建议（决策点 C1）：改用 **Obsidian 约定 `![alt|300x200](path)`**（alt 携带尺寸，生态可读、往返 OK）

## Requirements
- R1 **往返修复（P0）**：写盘路径不再产生「图消失」；至少保证**坏语法至少不丢图**（能降级为可渲染）
- R2 **尺寸语法**：支持 Obsidian 约定 `![alt|WxH](path)`；对我方历史自研 `=WxH` 提供**读兼容**（不强制迁移用户已有文件）
- R3 **拖拽缩放**：图片右下角手柄拖拽改尺寸 → 写回尺寸语法（往返可解释）
- R4 **语义化渲染**：本地/远程 src 解析走 host adapter（`md-core` 的 `resolveImageSrc` 已就位）；`srcset`/`alt`/题注
- R5 **灯箱**：点击放大（既有 `image-lightbox` 走 host 注入，不得让包依赖宿主）
- R6 编辑态与预览态**零差异**（遵循 parity 门禁）

## Acceptance Criteria（四类 UI 测试齐备）
- [ ] 渲染：`![a](p)` / `![a|300x200](p)` / `![a](p =300x200)` 三种写法都渲染出正确尺寸
- [ ] 编辑：进入编辑态与预览态 computed style 一致；拖拽缩放后写盘内容正确
- [ ] 往返：三种写法**逐字节可解释**；坏语法**至少不丢图**；尺寸改动只改尺寸不重排全文
- [ ] 样式：断言宽度/对齐/圆角/题注字号取自既有 token（无新增颜色）
- [ ] 沙箱实测：在草稿笔记里插入→缩放→失焦→重开，图片仍在且尺寸正确

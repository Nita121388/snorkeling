# CommonText 列表元信息 + 排序控件落地

## 背景

`design/prototypes/commontext-list-meta-sort/`（2026-11-05 提交 `32a40254`）已把真实双栏
Master-Detail 镜像出来，并加了两个新增点。真实组件（`frontend/app/commontext/`）尚未改造。

需求原话：CommonText 列表要展示创建时间 / 更新时间 / 支持多排序 / 显示使用次数。

## 交付物

1. **列表行右侧「使用次数 + 更新时间」列**：图标 + 数字，不新增整行、不抬高行高；
   完整时间戳与「used N time(s)」下沉到 tooltip。
2. **左栏搜索框下方的排序控件**：纯图标按钮组（遵守「能图标不用文字」），
   5 个排序键 + 搜索态相关度提示 + 置顶常驻提示；选择持久化，重开保留。
3. **详情区页脚元信息**：创建 / 更新 / 最近使用 / 次数 四组图标 + 紧凑时间。
4. **排序数据层**：新增 `sortCommonTextItemsBy(items, key)`，`sortCommonTextItems` 行为不变。
5. **使用次数口径修正**：补 `Copy` 与列表行 hover 插入两个写入点；新建条目不再虚记 1 次。

## 已定的设计决策（采纳原型推荐值）

| 决策 | 结论 |
|---|---|
| 「时间 + 次数」放哪 | 右侧对齐一列小字，完整时间走 tooltip（不新增整行） |
| 搜索时排序 | 浏览态用用户排序；搜索态相关度优先，排序控件禁用 + 相关度图标点亮 |
| 排序函数 | 独立注入，不改 `sortCommonTextItems`（它还决定写盘顺序与 ↑↓ 落点） |
| 置顶 | 两种状态都置顶最前；搜索态只作并列次序 |

## 验收标准

- 列表每条都能看到「次数 + 相对更新时间」，行高与改造前一致（不出现换行挤压）。
- 点排序按钮后列表立即重排；第 10 次打开弹窗仍保持上次选择。
- 搜索框有字时列表按相关度排，排序按钮为禁用态并显示相关度图标。
- 详情 Copy 与行内 hover 插入后，该条 `usagecount` +1、`lastusedat` 刷新。
- 新建条目 `usagecount` 保持 0（不再虚记 1 次），但仍排在「最近使用」前排。
- `sortCommonTextItems` 的既有行为与单测全绿。

## 非目标

- 不做编辑器联想 / 键盘导航 / 自动保存逻辑的改动。
- 不引入 i18n（该弹窗现有文案就是硬编码英文）。
- 不改 `loop/`、`scripts/verify/` 既有 area（真机验证单独评估）。

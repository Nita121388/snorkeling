# txt 内部预览 + html 三种打开模式

## Goal

1. `.txt` 文件能在 Snorkeling 内部预览（当前似乎不支持）。
2. `.html` 文件支持三种明确打开方式：看源码 / 内部渲染预览 / 系统默认应用，并有清晰的交互区分。

## 现状

- 预览类型由 `frontend/app/view/preview/preview-model.tsx` 的 `specializedView` 分派（如 `markdown`、`codeedit`、`directory`）
- 未见对 `.txt` 的明确路由
- `.html` 无多模式选择入口

## Requirements

### txt 内部预览

- `.txt` 打开时使用内置文本视图（复用现有代码编辑/纯文本视图），显示为只读文本
- 不得回退到"无法预览"或"用外部应用打开"
- 大文件（例如 >2MB）要有保护：截断或提示，不得卡死 UI

> 实施前先确认真实原因：可能是 MIME 判定、也可能是 `specializedView` 未覆盖 `.txt`。以实测为准，不要照搬假设。

### html 三种打开方式

- 三个显式入口：**源码**（文本视图，可只读展示 HTML 文本）、**内部预览**（渲染后的页面）、**系统默认应用**（外部浏览器）
- 交互方案（已确认）：
  - **双击 = 使用上次选择的模式**
  - 右键菜单 / 工具栏提供三个显式选项
  - 每个扩展名记忆偏好（复用已有的 path-usage / path-panel 存储模式）
- 首次打开且无记忆偏好时，默认「内部预览」

### 安全与隔离

- 内部预览渲染不可执行会破坏应用上下文的脚本；如需支持脚本，必须隔离（iframe sandbox 等）

## Acceptance Criteria

- [ ] 打开 `.txt` 可在 Snorkeling 内部看到内容
- [ ] 打开 `.html` 可选源码 / 内部预览 / 系统默认应用三种方式
- [ ] 双击 `.html` 沿用上次选择的模式
- [ ] 每个扩展名的偏好可持久化，重启后仍生效
- [ ] 大 `.txt` 不导致 UI 卡死
- [ ] html 内部预览不破坏应用上下文
- [ ] 有单元测试覆盖模式选择与偏好读写

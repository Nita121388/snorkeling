## 1. 边界

**做**（A1）：`pkg/persona` 纯文件系统包 + `wsh persona create/list/get/rename` 本地 CLI。

**不做**（明确出界）：
- `persona:rootdir` 设置项 / `relocate` → A5.5
- AISessions 的 `persona` 属性 / 🎭 分组 / 登场史 → A1.5
- widget 🎭、hover 弹窗、登场注入 → A3
- 名册 Block `persona://` → A4
- MCP 工具 / proposals 闸门 / 配额 / createdBy 的批准流 → A2.5
- emoji → AgentIcon 更名 → R0

## 2. 包契约（`pkg/persona`）

不依赖 DB、不依赖 RPC、不 import `pkg/wcore`。只 import 标准库。
理由：CLI 与未来 MCP 工具共用同一套落盘逻辑；无 DB 保证「记忆纯 Markdown」不变式（§3.6）。

```go
// 根目录解析：显式参数 > PERSONA_ROOT 环境变量 > ~/.snorkeling/personas
func DefaultRootDir() (string, error)
func ResolveRoot(explicit string) (string, error)

type Options struct {
    Root      string   // 空 = DefaultRootDir
    Name      string   // 显示名；目录 id 由 slug(name) 派生
    Emoji     string
    Role      string   // 一句话职责，进名册 L0
    Provider  string
    Model     string
    DryRun    bool     // 默认 true，由 CLI 传
    CreatedBy *Provenance
    Origin    *Origin
}

type PlannedFile struct { Path, Bytes string }   // Bytes = 预览内容（截断）
type CreateResult struct {
    Persona   Persona
    Dir       string
    Files     []PlannedFile
    Created   bool   // false = 已存在、幂等命中
    Applied   bool   // 是否真的落盘
}

func Create(opts Options) (*CreateResult, error)     // 幂等：目录已存在 → Created=false, exit 0
func List(root string) ([]Persona, error)            // 扫描 <root>/<id>/.persona/persona.json
func Get(root, id string) (*Persona, string, error)  // 返回档案 + CHARTER 原文
func Rename(root, oldID, newID string, dryRun bool) (*RenameResult, error)
func RosterPath(root string) string                  // <root>/.index/PERSONAS.md
func WriteRoster(root string) (string, error)        // 幂等重生成
```

**slug 规则**：小写化 → 非字母数字/`-`/`_` 折叠为 `-` → 去首尾 `-` → 空则 `persona`。
中文名 → 无法派生可读 slug 时回落 `persona-<4位随机>`？**不用随机**（幂等要求可复现）：
中文/纯符号名 → `persona-<name 的 8 位 hex sha1>`，同输入同输出，仍幂等。`--id` 不开放。

**幂等语意**：`Create` 先看 `<root>/<slug>/.persona/persona.json` 是否存在；存在则读回、不写任何文件、返回 `Created=false`。dry-run 只做计算，绝不 `MkdirAll`。

## 3. 落盘清单（scaffold，全部幂等）

```
<root>/<id>/.persona/persona.json          # 身份卡（无 GENERATED 头，是源）
<root>/<id>/.persona/persona.local.json    # 本机专属
<root>/<id>/.persona/CHARTER.md            # 唯一真源（模板骨架，人写）
<root>/<id>/.persona/MEMORY/facts.md       # 带 ## TL;DR 空节
<root>/<id>/.persona/MEMORY/lessons.md
<root>/<id>/.persona/MEMORY/journal.md
<root>/<id>/.persona/MEMORY/inbox.md
<root>/<id>/.persona/MEMORY/playbook/.gitkeep
<root>/<id>/.persona/MEMORY/archive/.gitkeep
<root>/<id>/.persona/agents/AGENTS.md      # GENERATED
<root>/<id>/.persona/agents/CLAUDE.md      # GENERATED
<root>/<id>/.persona/agents/GEMINI.md      # GENERATED
<root>/<id>/AGENTS.md                      # GENERATED，≤ 20 行
<root>/<id>/work/.gitkeep
<root>/<id>/.gitignore                     # §3.2 清单
```

`.persona/` 下 12 个文件 → 满足判据 `>= 9`。

**GENERATED 头**统一一行 HTML 注释（Markdown）：
`<!-- GENERATED by wsh persona; edit .persona/CHARTER.md or MEMORY/ instead. -->`
JSON 无注释语法，改用字段 `"_generated": "wsh persona scaffold v1"`。

**根级 AGENTS.md ≤ 20 行**：指针（先读 `.persona/MEMORY/`）+ 同事规则（读名册、改动走 inbox）+ 产物进 `work/`。

## 4. 名册

`<root>/.index/PERSONAS.md`，每次 create/rename 后重生成；`list` 不写盘也可用扫描结果。
行格式（L0，一行一人设）：

```
🎭 backup-guard | 备份归档 | pi/deepseek | ./
```

头部两行标注 GENERATED + 扫描时间。超过 50 人设时追加一行折叠提示（真正的分组维度留给 A4，§12 开放问题 1）。

## 5. rename

1. `--dry-run` 默认：打印 `old → new` 与将改写的引用清单
2. `--yes`：`os.Rename`（同卷原子）；更新 `persona.json.id` 为 newID；重写名册
3. **block meta `persona:id` 引用重写**：`persona:id` 由 A3 才写入 block meta，A1 阶段恒为空集 → 代码留 `rewriteBlockMetaReferences` 钩子（返回 0），A3 接 RPC 实现。这是**有意的不做**，写进 PRD 差异说明。
4. 目标目录已存在 → 报错 exit 1，不覆盖。
5. 名册里新 id 出现，旧 id 0 次出现（判据）。

## 6. CLI

```
wsh persona create --name <n> [--emoji] [--role] [--provider] [--model] [--json] [--yes] [--root]
wsh persona list [--json] [--root]
wsh persona get <id> [--json] [--root]
wsh persona rename <old> <new> [--json] [--yes] [--root]
```

- 写命令默认 dry-run；`--yes` 才落盘；dry-run 退出码 0
- 幂等命中退出码 0，stdout 明说「已存在，未改动」
- `--json` 一律输出结构化对象（不混人类可读文本）
- 命令组注册在 `cmd/wsh/cmd/wshcmd-persona.go`，`rootCmd.AddCommand`
- **不走 RPC**：本地 pure-fs 操作。→ `wsh persona` 在 app 未启动时也可用（数据地基不该依赖 GUI）

## 7. scope 门的落点（PRD「data scope」的兑现口径）

`agentscope` / `agentguide` 管的是**外部 agent 经 RPC/MCP 能做什么**。A1 只有本地 CLI（人跑），没有外部入口：
- A1：包内导出 `const Scope = "data"`，文档注明写入类操作属 data 级
- A2.5：MCP `persona.create` / `persona.memory.add` 注册进 `agentguide` + `agentscope.commandScopes` 时强制 data

在 A1 提前往 commandScopes 塞不存在的 command 只会制造假门，故不做。**这是对 PRD 的唯一主动收窄，需在验收记录里写明。**

## 8. 兼容与回滚

- 新包 + 新命令文件，不改既有符号 → 影响面 = 新增
- 回滚：删 `pkg/persona/`、`cmd/wsh/cmd/wshcmd-persona.go`、`pkg/persona/**` 测试；已生成的人设目录是用户数据，**不删**
- 默认 root `~/.snorkeling/personas/` 首次 create 才建目录，不预建

## 9. 风险

| 风险 | 处理 |
|---|---|
| Windows 下 `os.Rename` 跨盘失败 | A1 只做同 root 内 rename；跨盘搬家属 A5.5 `relocate` |
| 中文名 slug 不可读 | 固定 hash 后缀，可复现；显示名仍在 `persona.json.name` |
| 名册并发写（两侧同时 create） | 先写临时文件再 `os.Rename` 原子替换 |
| 未来 A5.5 加 rootdir 设置 | `ResolveRoot` 已留显式参数入口，只加设置读取一行 |

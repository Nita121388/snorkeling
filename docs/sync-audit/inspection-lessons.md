# Snorkeling 巡检教训库（inspection-lessons）

> append-only：每轮巡检完追加一条，永不修改历史行。
> 教训来源：巡检发现的问题模式 → 下次该加什么检查规则 → 升级检查器/SKILL。
> 升级动作本身记录在 `evolution-log.md`。

## L01（2026-08-04）：同步的单位是功能模块，不是文件

- **问题模式**：原设计把「文件存在性」当同步主检（L1 硬查），用户指出伪命题：**文件会迁移，功能不会死**。
  只查「scanshells.go 在不在」无法回答「shell 切换这个功能，代码/原型/方案三处说的还是一回事吗」。
- **认知修正**：同步 = 功能模块三处对齐（代码 ⇄ 原型 ⇄ 方案）。文件迁移不改模块基线。
  深度巡检先对齐核心模块，基线稳定后由 git commit 驱动增量巡检。
- **下次规则**：巡检先问「这个模块三处一致吗」，而不是「这个文件存在吗」。
  文件地址失效时，先做模糊匹配找迁移线索（近名/同目录/函数名），有线索自动接上，无线索才升级人工。

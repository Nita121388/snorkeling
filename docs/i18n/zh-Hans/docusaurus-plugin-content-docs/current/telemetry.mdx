## 简短版 {#tldr}

Snorkeling 当前仍继承 Wave Terminal 的遥测和诊断 ping 代码路径。默认配置中包含 `"telemetry:enabled": true`，运行时也仍然为了兼容使用若干上游 `WAVETERM_*` 环境变量。

继承的遥测代码设计上不会收集个人身份信息 (PII)、按键、文件内容、AI 提示词、IP 地址、主机名或命令。事件会关联到一个匿名、随机生成的 _ClientId_ (UUID)。你可以随时选择退出。

如果启用，继承的遥测系统可能收集以下摘要信息：

- 基础应用/系统信息：操作系统、架构、应用版本、更新设置
- 使用指标：应用启动/关闭、活跃分钟数、前台时间、标签页/block 数量和使用情况
- 功能交互：创建标签页、执行命令动作、修改设置等
- 显示信息：显示器分辨率、显示器数量
- 连接事件：SSH/WSL 连接尝试，但不包含主机名或 IP
- AI 使用元数据：模型/提供商选择、token 数量、请求指标和延迟，但不包含提示词或响应
- 错误报告：崩溃/panic 事件及最少量调试信息

## 如何禁用遥测 {#how-to-disable-telemetry}

可以在 Snorkeling 的通用配置文件中将 `telemetry:enabled` 设置为 `false` 来禁用遥测。也可以使用下面的命令禁用：

```bash
wsh setconfig telemetry:enabled=false
```

## 诊断 Ping {#diagnostics-ping}

Snorkeling 当前仍保留继承的诊断 ping 路径。该 ping 与使用遥测分离，用于估算活跃安装量和仍在使用的版本。

这个 ping 只包含应用版本、OS/CPU 架构、本地日期、匿名客户端 ID，以及使用遥测是否启用。它不包含命令、文件、提示词、响应、主机名、IP 地址或遥测事件。

如需禁用诊断 ping，请在启动 Snorkeling 前设置 `WAVETERM_NOPING` 环境变量。该变量名仍继承自上游 Wave。

## 发送遥测 {#sending-telemetry}

如果启用了遥测，Snorkeling 首次启动后不久会发送一次，之后也会周期性发送。关闭应用时也可能发送。遥测发送后，事件会被标记为已发送，以避免重复传输。

### 启用遥测后发送 {#sending-once-telemetry-is-enabled}

一旦启用遥测，无论距离上次发送过去多久，都可能立即发送一次遥测更新。这不会重置常规遥测发送计时器。

### Snorkeling 关闭时 {#when-snorkeling-is-closed}

如果启用了遥测，Snorkeling 关闭时可能会发送遥测。

## 事件类型和属性 {#event-types-and-properties}

完整事实以当前源代码为准。相关实现区域包括 `pkg/telemetry`、`pkg/wcloud`、`pkg/wcore`，以及 `pkg/wconfig/defaultconfig/settings.json` 中的 `telemetry:enabled` 默认值。

## GDPR 退出合规 {#gdpr-opt-out-compliance}

禁用遥测时，继承的代码路径可能会发送一条与匿名客户端 ID 关联的最小退出记录，用于记录遥测已关闭以及关闭时间。之后，只要遥测保持禁用，就不应继续发送遥测或使用数据。

## 删除你的数据 {#deleting-your-data}

Snorkeling 当前没有在本仓库中记录独立的公开数据删除支持渠道。如果项目后续发布 Snorkeling 专属遥测后端或支持流程，应先更新本页，再声明删除流程。

## 隐私政策 {#privacy-policy}

Snorkeling 当前没有在本仓库中发布独立隐私政策。请将本页视为实现说明，而不是法律意义上的隐私政策。

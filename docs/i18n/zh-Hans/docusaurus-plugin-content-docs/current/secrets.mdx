# 密钥 {#secrets}

<VersionBadge version="v0.13" noLeftMargin={true} />

Snorkeling 提供了一种安全方式来存储密码、API key 和令牌等敏感信息。密钥会加密存储在系统原生钥匙串中（macOS Keychain、Windows Credential Manager 或 Linux Secret Service），确保敏感数据受到保护。

## 为什么使用密钥？ {#why-use-secrets}

Snorkeling 中的密钥可以让你：

- **存储 SSH 密码** - 自动为 SSH 连接认证，无需反复输入密码
- **管理 API key** - 安全保存 API token、key 和凭据
- **跨会话共享** - 从任意终端 block 或远程连接访问密钥
- **避免明文存储** - 不再把敏感数据存放在配置文件或脚本中

## 打开密钥 UI {#opening-the-secrets-ui}

可以通过几种方式访问密钥管理界面：

1. **从 widget 栏打开**（推荐）：
   - 点击 widget 栏上的 **<i className="fa-gear fa-solid fa-sharp"/>** 设置图标
   - 在菜单中选择 **Secrets**

2. **从命令行打开：**
   ```bash
   wsh secret ui
   ```


密钥 UI 提供可视化界面，用于查看、添加、编辑和删除密钥。

## 通过 CLI 管理密钥 {#managing-secrets-via-cli}

Snorkeling 提供完整的 CLI，可从任意终端 block 管理密钥：

```bash
# 列出所有密钥名称（不显示值）
wsh secret list

# 获取指定密钥值
wsh secret get MY_SECRET_NAME

# 设置密钥（格式：name=value，= 两侧不要有空格）
wsh secret set GITHUB_TOKEN=ghp_xxxxxxxxxx
wsh secret set DB_PASSWORD=super_secure_password

# 删除密钥
wsh secret delete MY_SECRET_NAME
```

## 密钥命名规则 {#secret-naming-rules}

密钥名称必须匹配以下模式：`^[A-Za-z][A-Za-z0-9_]*$`

这意味着：
- 必须以字母开头（A-Z 或 a-z）
- 只能包含字母、数字和下划线
- 不能包含空格或特殊字符

**有效名称：** `MY_SECRET`、`ApiKey`、`ssh_password_1`
**无效名称：** `123_SECRET`、`my-secret`、`secret name`

## 在 SSH 连接中使用密钥 {#using-secrets-with-ssh-connections}

<VersionBadge version="v0.13" />

密钥可用于自动为 SSH 连接提供密码，避免重复输入密码。

### 在 connections.json 中配置 {#configure-in-connectionsjson}

在连接配置中添加 `ssh:passwordsecretname` 字段：

```json
{
    "myserver": {
        "ssh:hostname": "example.com",
        "ssh:user": "myuser",
        "ssh:passwordsecretname": "SERVER_PASSWORD"
    }
}
```

然后将密码存储为密钥：

```bash
wsh secret set SERVER_PASSWORD=my_actual_password
```

现在，当 Snorkeling 连接到 `myserver` 时，会自动使用密钥存储中的密码，而不是提示你输入。

### 优势 {#benefits}

- **安全**：密码会加密存储在系统钥匙串中
- **方便**：每次连接时无需输入密码
- **灵活**：更新密码时只需修改密钥，而不必修改配置

## 安全注意事项 {#security-considerations}

- **加密存储**：密钥会以加密形式存储在 Snorkeling 配置目录中。加密 key 本身由操作系统的安全凭据存储保护（macOS Keychain、Windows Credential Manager 或 Linux Secret Service）。

- **无明文**：密钥永远不会以未加密形式存储在日志或可访问文件中。

- **访问控制**：密钥只能由 Snorkeling 访问。


## 存储后端 {#storage-backend}

Snorkeling 会自动检测并使用适合当前操作系统的密钥存储后端：

- **macOS**：使用 macOS Keychain
- **Windows**：使用 Windows Credential Manager
- **Linux**：使用 Secret Service API（freedesktop.org 规范）

:::warning Linux Secret Storage
在 Linux 系统上，Snorkeling 需要兼容的 secret service 后端（通常是 GNOME Keyring 或 KWallet）。这些通常会随桌面环境预装。如果没有检测到兼容后端，你将无法设置密钥，UI 也会显示警告。
:::

## 故障排查 {#troubleshooting}

### "No appropriate secret manager found" {#no-appropriate-secret-manager-found}

在 Linux 上，如果没有可用的兼容 secret service 后端，就会出现该错误。请安装 GNOME Keyring 或 KWallet，并确保 secret service 正在运行。

### Secret not found {#secret-not-found}

请确认密钥名称拼写正确（名称区分大小写），并确认该密钥确实存在：

```bash
wsh secret list
```

### Linux 上 Permission denied {#permission-denied-on-linux}

secret service 可能要求你解锁钥匙串。这通常发生在登录之后。关于钥匙串管理，请参考你的桌面环境文档。

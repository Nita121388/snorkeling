# FAQ

### Is Snorkeling the same as Wave Terminal?

No. Snorkeling is a customization fork built on top of Wave Terminal. It inherits many Wave capabilities, then adds Snorkeling-specific workflows such as Agent launch, AI Sessions browsing, Files improvements, Version Control blocks, and Snorkeling release packaging.

### Why do some names still say Wave or WAVETERM?

Some command names, config keys, environment variables, package names, and internal code paths still use upstream Wave names. The most visible examples are the `wsh` CLI, the `WAVETERM_*` environment variables, and the inherited `waveai:*` configuration keys. These are runtime compatibility facts, not documentation typos.

### How can I see the block numbers?

The block numbers appear when you hold down Ctrl-Shift and disappear once you release the key combo.

### How do I make a remote connection?

There is a button in the header. Click the <i className="fa-sharp fa-laptop"/> or <i className="fa-sharp fa-arrow-right-arrow-left"/> icon and type the `[user]@[host]` that you wish to connect to.

### On Windows, how can I use Git Bash as my default shell?

Snorkeling automatically detects Git Bash installations and adds them to the connection dropdown. Click the <i className="fa-sharp fa-laptop"/> or <i className="fa-sharp fa-arrow-right-arrow-left"/> button in the block header and select "Git Bash" from the list.

Alternatively, you can manually set Git Bash as your default shell by setting the configuration variable `term:localshellpath` to the location of the Git Bash `bash.exe` binary. By default it is located at `C:\Program Files\Git\bin\bash.exe`.

Remember that backslashes need to be escaped in JSON:

```json
"term:localshellpath": "C:\\Program Files\\Git\\bin\\bash.exe"
```

### Can I use wsh outside of Snorkeling?

`wsh` is an internal CLI for extending control over Snorkeling to the command line. To prevent misuse by other applications, `wsh` requires an access token provided by Snorkeling for most app-control operations and will not behave as a standalone general-purpose CLI.

### Why does Snorkeling warn me about ARM64 translation when it launches?

macOS and Windows both have compatibility layers that allow x64 applications to run on ARM computers. This helps more apps run on these systems while developers work to add native ARM support, but it can have performance costs.

For the best experience, use a Snorkeling build that matches your machine architecture. You can find available artifacts on the [Snorkeling GitHub Releases page](https://github.com/Nita121388/snorkeling/releases).

You can disable this warning by setting `app:dismissarchitecturewarning=true` in [your configuration](./config).

### How do I get Snorkeling beta or release builds?

Snorkeling builds are published from the `Nita121388/snorkeling` repository. Use the [GitHub Releases page](https://github.com/Nita121388/snorkeling/releases) and download the artifact for your platform.

Do not use upstream Wave package-manager commands if you intend to install Snorkeling; they install Wave Terminal.

### Can I use inherited Wave AI features without enabling telemetry?

<VersionBadge version="v0.13.1" noLeftMargin={true}/>

Yes. Inherited Wave AI cloud modes may depend on telemetry-related settings, but you can use your own custom AI mode with a local model or your own API key.

To use AI without telemetry:

1. Configure a custom AI mode. See [AI Modes](./waveai-modes).
2. Set `waveai:defaultmode` to your custom mode's key in Snorkeling settings.
3. Set `telemetry:enabled=false` if you want telemetry disabled.

After that, Snorkeling can use providers such as Ollama, OpenAI-compatible APIs, OpenRouter, or others through your own configuration.

## AC7 机制定位（DB 直查，决定性证据）

对 `.runcfg/verify-acs/data/db/waveterm.db` 只读查询：

```
tab e67fd3e1 name=T1         blocks=4  layout=fdcadb31
tab d3153e08 name=acs-verify blocks=1  layout=ab0ee842

layout fdcadb31  pending=0  leaforder=1
layout ab0ee842  pending=2  leaforder=0
   pending: {"actiontype":"clear"} / {"actiontype":"insertatindex","blockid":"d07953e7..."}
```

读法（只陈述测得的事实）：

1. **`syncState` 只看 `tab.BlockIds` 是否含新块**，不看布局动作队列是否被消费。
   `T1` 的 `BlockIds=4`（含我创建的 3 个），但渲染模型 `leaforder=1`。
2. 发往**从未在前端显示过的 tab**（`acs-verify`）的动作仍堆在
   `pendingbackendactions`（2 条，含 `clear` + `insertatindex`）→ 前端没有消费。
3. 发往**当时活动 tab**（`T1`）的动作 `pending=0`（已消费），但 `leaforder` 仍是 1
   → 前端处理了却没有长出叶子。

**结论**：`syncState = layout-applied` 只表达「后端已把 block 写进 tab」，
既不代表前端收到动作，也不代表前端渲染出来。要让 Agent 判断「真的画出来了」，
`--wait` 的判据必须换成「`pendingbackendactions` 排空 **且** `leaforder` 含该 block」，
或在 `--wait` 里加前端回执。→ 建议进 P0.3 / 后续修正，不在 P0.2 交付范围内。

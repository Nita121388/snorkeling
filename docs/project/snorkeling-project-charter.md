## 1. 项目目标

在 Wave Terminal 官方仓库基础上，开发定制化终端项目 **浮潜（Snorkeling）**，目标是：

- 结构清晰、环境隔离、可小步迭代，避免历史混乱分支复用带来的污染
- 引入 OpenCove 的 Agent 管理理念，形成可维护的 Agent 启动与配置体系
- 建立完整 CI/CD，支持 macOS / Linux / Windows 自动构建与 Release 发布
- 保持后续可持续同步官方更新并重新打包发布

## 2. 硬约束（必须满足）

- 必须与本机历史目录 `/Users/nita/Primary/projects/waveterm` 的旧分支/旧配置彻底解耦
- 新开发必须基于官方 Wave 仓库干净分支进行
- 采用小步提交、分步汇报、每步可验证的开发方式
- 任何关键需求都要落入仓库文档，不依赖聊天上下文

## 3. 功能需求基线

### 3.1 右侧按钮列新增 Agent

- 在主界面右侧 widgets 列中，将 `Agent` 按钮放在 `Terminal` 与 `Files` 之间
- 图标语义要求：优先使用“浮潜/潜水/面镜”相关视觉语义（当前阶段先采用可用占位图标，后续可替换）

### 3.2 智能打开 Agent（核心行为）

点击 `Agent` 后按以下规则执行：

1. 场景一（仅本地）：当前 Tab 只有本地终端上下文时，直接打开本地 Agent
2. 场景二（仅远程）：当前 Tab 只有单一远程终端上下文时，直接打开该远程 Agent
3. 场景三（多终端/混合）：当前 Tab 存在多个或混合终端上下文时，弹出简洁选择弹窗，让用户明确选择目标终端环境

### 3.3 Agent 配置机制

- Agent 配置管理（连接、环境变量、模型等）需参考 OpenCove 的实现思路
- 不是简单硬编码命令，要形成可扩展、可配置、可测试的配置层

## 4. 工程与交付要求

### 4.1 开发流程

- 先给行动计划，再执行代码
- 每步完成后暂停并说明：做了什么、为什么、下一步是什么

### 4.2 CI/CD

- GitHub Actions 自动化构建（macOS / Linux / Windows）
- 自动产出 Release 构件与版本发布流程

### 4.3 官方同步能力

- 确保后续可以持续跟进官方版本并重新打包发布

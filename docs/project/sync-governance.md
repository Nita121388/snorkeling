## 1. 目标与范围

让四类资产（代码 / 事实源文档 / 文档站镜像 / Obsidian 管理视图）保持一致，提供：

1. **自动检查**：L1 脚本硬查 + L2 Agent 软查，无需人工即可发现脱节。
2. **登记**：所有发现落盘 `docs/project/TODOS.md`，带建议强度与证据。
3. **审批**：本地 HTML 逐条/批量审批，ADHD 友好。
4. **执行与回滚**：每个修改独立 git commit + 修改前快照，可 `git revert`。
5. **验证关闭**：重跑检查确认消除后移入 ✅已关闭。

范围外：不做全自动修改（修改永远人工审批）；不做 web 服务/数据库（纯本地文件）；不做 cron 定时器。

## 4. L1 硬查规格（audit-sync.mjs 扩展）

### 4.1 检查项

| 检查 | 方法 | 输出级别 |
|---|---|---|
| 镜像文件存在性 | README 状态标记的「镜像源」→ `existsSync` | 缺失=🔴 |
| 镜像时间戳 | 镜像文件 mtime vs README「最后同步」 | mtime 更新=🟡 |
| 版本号变化 | `package.json` version vs 上次记录（TODOS 头部存基线） | 变化=🟡「需巡检」 |
| 原型结构特征 | README「结构特征」清单 vs 真实组件 grep | 特征消失=🔴 |
| 文档引用完整性 | docs .mdx 引用的事实源章节 vs 事实源存在 | 缺失=🔴 |

### 4.2 README 状态标记（原型侧，已有 PROCESS.md 约定，扩展）


## 5. L2 软查规格（SKILL：snorkeling-sync-audit）

### 5.1 检查清单（agent 执行，语义判断）

| 检查 | 输入 | 方法 | 输出 |
|---|---|---|---|
| 原型 vs 组件 | 原型 HTML + 真实 .tsx | 比对结构层次/类名/文案 | 🔴 结构已变 / 🟡 疑似 / 🟢 对齐 |
| 功能描述 vs 代码 | docs .mdx + grep | grep 功能关键词在 frontend/pkg 是否命中 | 🔴 描述已过时 / 🟢 在 |
| 07-TODO vs 代码 | Obsidian 07-TODO 项 | grep 验证是否落地 | 已落地未勾=🟢「补勾」 |
| 事实源 vs 新 commit | git log 近期 commit | 判断新功能是否进事实源 | 缺失=🟡「登记入事实源」 |

### 5.2 输出（结构化，供审批界面读取）

每条：`{id, level, asset, title, reason, evidence, suggestion}`

### 5.3 运行时机

- 开发会话收尾（agent 自动提示）
- 手动：「巡检」「检查原型」
- L1 报告存在 🔴/🟡 时

### 6.2 字段

- `ID`：P + 递增序号（跨月延续）
- `级别`：🔴 / 🟡 / 🟢（🟢 默认批量通过，审批界面仍记录）
- `资产`：原型/文档/代码/Obsidian 的路径
- `问题`：一句话
- `建议`：处理建议（含建议强度）
- `证据`：代码位置/目录现状/grep 结果
- `commit`：关闭时填执行的 commit 号

## 7. 审批界面规格（docs/project/approval-ui.html）

### 7.1 技术要求

- 单文件 HTML + 内联 CSS/JS，无外部依赖，双击浏览器打开
- 数据源：同目录 `TODOS.md`；读写用 File System Access API；不可用则降级为「复制粘贴」模式（textarea 粘 JSON，点保存下载新 TODOS）
- 进度存 `localStorage`（key：`snorkeling-approval-progress`），随时退出续审

### 7.2 UI 布局（逐条）

```
┌─ Snorkeling 同步审批 ───────────── 第 3/12 条 · 完成 25% ─┐
│ ████████░░░░░░░░░░░░░░░░░░░░░                              │
│  🟢 建议通过                                              │
│  shell-settings 镜像源已失效                               │
│  pkg/util/shellutil/scanshells.go 已不存在（全仓 0 引用）  │
│  处理建议: 更新镜像源为 shellutil.go（纯引用修正）          │
│  [证据] ▸ pkg/util/shellutil/ 目录现状（可点开）           │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌──────┐                │
│  │ ✅通过 │ │ ❌拒绝 │ │ 💬批注 │ │ ⏭稍后│                │
│  └────────┘ └────────┘ └────────┘ └──────┘                │
└─────────────────────────────────────────────────────────────┘
```

### 7.3 交互

- 一次只显示 1 条（单任务聚焦）
- 键盘：`1`通过 / `2`拒绝 / `3`批注 / `4`稍后 / `g`批量通过🟢
- 顶部「先批量通过所有🟢」按钮（🟡🔴 不受影响，必逐条）
- ❌/💬/⏭ 弹**必填**输入框（textarea + 确认）；❌=拒绝理由，💬=你的原话批注
- 💬 批注后条目进入 `💬待回复`：agent 按批注修订建议 → 重新生成条目 → 回审批
- 证据区默认折叠，点击展开（含目录列表/grep 输出）
- 底部「完成」汇总：通过 x 条 / 拒绝 y 条 / 批注 z 条 / 挂起 w 条 → 导出更新后的 TODOS.md
- **「已自动修正」区**：自动执行的机械修正（版本号/日期/路径）集中展示，可逐条回滚

### 7.4 数据格式（界面 ↔ TODOS 交换）

界面读入：解析 TODOS.md 的 ⏳待审批 表格 → JSON 数组。
回写：按 ID 把每条状态更新到对应分区表，重排序号。

## 8. 执行与回滚

### 8.0 自动审查 vs 人工审批边界（三问决策规则）

判断一个动作要不要人工审批，问三问，**中任何一个就必审批**：

| 问题 | 中招→ | 例 |
|---|---|---|
| ① 会**删东西**吗？ | 🔴 必审批 | 删原型、移 _to-delete |
| ② 会**改行为**吗？（影响用户看到的界面/功能） | 🔴 必审批 | 改结构、标记功能移除、升级 SKILL |
| ③ 没有客观证据、无法自动验证？ | 🔴 必审批 | "布局好像变了"这类模糊判断 |

**三问全不中 → 自动执行**：版本号过期、镜像路径失效、日期/status 字段。
这类是机械事实修正，改错可 revert，不打扰用户。

**自动 ≠ 不看**：自动执行的每条都留在审批界面「已自动修正」区，
随时可翻到、可回滚。

### 8.1 执行纪律（agent 遵循）

1. 每个审批通过的修改**单独一个 commit**（一个 P 一条 commit，或显式关联）。
2. commit message 带 `sync-governance: P01 ...` 前缀，关联登记表 ID。
3. 修改前记录 diff：`git diff HEAD -- <files>` 存 `docs/project/snapshots/<ID>-before.diff`。
4. 不混入无关改动（如 package-lock 自动变化需单独处理）。

### 8.2 回滚

- 单条回滚：`git revert <commit>`。
- 批量回滚：按 commit 列表逐个 revert（记录表可追溯）。
- 快照兜底：即使 revert 冲突，可用 `snapshots/<ID>-before.diff` 手工还原。

## 10. 验收标准

系统落成后应满足（可逐项验证）：

1. `node .mockup/audit-sync.mjs` 能输出分级报告，退出码正确。
2. `docs/project/TODOS.md` 有基线 + 空待审批表，格式符合 6.1。
3. 打开 `docs/project/approval-ui.html` 能加载待审批表、逐条审批、批量绿灯、导出回写。
4. 首次巡检产生的条目（shell-settings 等）经审批后独立 commit + 快照，重跑检查后消除并关闭。
5. SKILL 在收尾时可一键触发软查并生成审批清单。
6. Obsidian `00-项目管理指南` 已引用本系统（新巡检流程指向 TODOS + 审批）。

## 12. 自我进化（巡检系统长记性）

每次巡检不仅检查，还要**升级自己**，下次更高效：

```
巡检发现问题 → 沉淀教训（问题模式 + 下次怎么查更高效）
    → 教训进审批（升级检查器＝改行为，需拍板）
    → 更新检查规则/SKILL → 下次巡检更强
```

- **教训库**：`docs/project/inspection-lessons.md`，每次巡检结束 agent 自动追加一条：
  - 问题模式（如"镜像源文件在 git 重构中被改名"）
  - 下次该加什么检查规则（如"先 diff 改名文件再查引用"）
- 教训库本身是新增文件（不删不改），自动写。
- **升级 SKILL/脚本**（会改行为）→ 进审批清单，用户拍板。
- 效果：第 1 次发现 shell-settings 镜像缺失；第 2 次自动先查镜像路径；
  第 3 次查得比人还细。系统用一次，强一次。

## 13. 演进备注

- 若审批负担仍高：批量绿灯升级为「🟢 自动执行」（需用户显式授权，默认不开）。
- 若跨会话频繁：可考虑给 TODOS 加 frontmatter 的 `updated` 日期 + Obsidian 侧 Base 视图镜像审批状态。
- 若需要远程/多机：Todo 文件走 git 同步天然满足。
